# Move the harness from `.aidlc/` to `.claude/harness/`

Date: 2026-09-18
Status: approved for planning

## Why

The harness is being narrowed to a single target runtime: Claude Code. The
repository currently keeps an agent-neutral core in `.aidlc/` and confines
Claude-specific material to `.aidlc/adapters/claude/` and `.claude-plugin/`.
`paths.mjs` states that intent in its header: *"The delivery protocol is
agent-neutral. Mutable artifacts, state, configuration, and the executable live
under `.aidlc/`. Provider directories such as `.claude/` are projections only."*

That split is now cost without benefit. This change collapses it: `.claude/` becomes
the single home, the adapter indirection is removed, and the neutrality language is
retired from code comments and docs.

## What this is not

This is a rename of a published contract, not an internal tidy-up. `.aidlc` is the
repo-root discovery probe (`paths.mjs:9`), the subject of the runtime identity
manifest, the target of `harness init`, and the path referenced by
`.claude-plugin/plugin.json`. Treating it as a cosmetic move is the main way this
change goes wrong.

## Decisions taken

| Decision | Choice | Rationale |
|---|---|---|
| Agent neutrality | Dropped | Claude Code is the only target |
| Core location | `.claude/harness/` | Leaves `.claude/skills/` and `.claude/agents/` free for the user's own |
| Skills/roles auto-load | Namespaced, not native | `.claude/skills/` auto-loads unconditionally; the project instruction requires the harness stay disabled in this repository |
| Backward compatibility | None | Hard cut; no `harness migrate`, no `.aidlc` fallback, no compat test |
| Local runtime state | Abandoned | `state/` (17 MB) and `evals/` (92 MB) are untracked; ledger, graph and last-check reset |
| Historical artifacts | Left untouched | See "The artifact asymmetry" |
| Execution | One atomic commit | Any partial state fails identity verification |

## The artifact asymmetry

`.aidlc/artifacts/` holds 70 change directories of `intent.md` / `spec.md` /
`plan.md` / `evidence.md` — the governance record of how this harness was built.
It is load-bearing at runtime: 16 modules under `lib/` and `checks/` read it, and
the generated `settings.json` grants `Write(.aidlc/artifacts/**)`. It moves with
the rest of the tree.

Its *prose* is not rewritten. Those files record what was true when each change
shipped; rewriting them would make past evidence cite paths that never existed.

This is safe because `artifacts.governingPlans` (`lib/artifacts.mjs:699`) returns
only the current change's plan, never the historical set:

```js
export function governingPlans(cfg) {
  const current = currentChange(cfg);
  return current?.plan ? [current.plan] : [];
}
```

`scope-drift.mjs`'s `unkeptProof` rule walks only that result, so the 49 historical
plans whose Proof rows name `.aidlc/` paths cannot fire findings. The one live risk
is the plan of whatever change is *current* at the time of the move; the move is
therefore performed with no change selected (see "Execution").

## The identity constraint

`lib/runtime-identity.mjs:10` pins the harness to its own paths:

```js
const roots = ['.aidlc/bin', '.aidlc/lib', '.aidlc/checks', '.aidlc/sensors',
               '.aidlc/hooks', '.aidlc/adapters', '.aidlc/skills', '.aidlc/roles',
               '.aidlc/templates', '.aidlc/policies', '.aidlc/instructions.md',
               '.claude-plugin'];
```

It hashes these exact path strings into a manifest digest, asserts
`.aidlc/bin/harness` is present or throws `runtime entrypoint missing`, and compares
the working tree against `git ls-tree HEAD` filtered by the same list. Two
consequences govern the whole change:

1. **No partial state can be green.** Half-renamed paths diverge from `HEAD`,
   `committed` goes false, identity verification fails. Hence one atomic commit.
2. **Every consumer install pin goes stale.** `examples/scratch-ts/.aidlc/harness-install.json`
   carries a sha256 over 62 manifest entries, 60 of them `.aidlc/...`. Pins are regenerated by `harness init`,
   never hand-edited. (That pin is already stale: it lists `skills/map/SKILL.md` and
   `sensors/test-quality.mjs`, neither of which exists. The re-`init` corrects this
   incidentally.)

This array is the single source for both the in-repo manifest and the copy embedded
in every generated 98-line consumer shim. Fixing it here fixes both.

## Execution

Performed as ordinary repository development, not through the harness's delivery
loop: the project instruction forbids creating `.aidlc/artifacts/` in this
repository, and the move must not be its own governed change. No change may be
selected as current while it runs.

1. `git mv .aidlc .claude/harness`; remove `state/`, `evals/`, `adapters/`.
2. Scripted rewrite across the six code areas; apply the hand edits above.
3. `rm -rf examples/scratch-*/.aidlc examples/scratch-*/.claude`; re-run `harness init`
   into both.
4. Regenerate `CLAUDE.md`, `CODEBASE-MAP.md`, `settings.json`, the hooks projection.
5. One commit.

## Acceptance criteria

1. `git grep '\.aidlc' -- . ':!.claude/harness/artifacts'` returns zero matches.
2. `git grep -c '\.aidlc' -- .claude/harness/artifacts` is unchanged at 6,371
   occurrences across 238 files.
3. `git log --follow` traverses the rename for a sampled moved file.
4. `node --test` passes.
5. `harness doctor` and `harness check --stage commit` pass on the committed tree.
   Identity verifies only against `HEAD`, so this is necessarily post-commit.
6. Both examples carry `.claude/harness/harness-install.json` with a manifest whose
   entries all begin `.claude/harness/` or `.claude-plugin`, and no entry names
   `skills/map/SKILL.md` or `sensors/test-quality.mjs`.
7. `.claude/skills/` and `.claude/agents/` are absent or empty; no harness skill
   auto-loads in this repository.
8. `.claude/settings.json` still disables the plugin here
   (`"lean-harness-cs-v1@lean-harness-cs-v1": false`).

## Out of scope

- `harness migrate`, any `.aidlc` fallback in `findRepoRoot`, any compat test.
- Preserving the abandoned `state/` and `evals/` directories. The tracked ratchet
  baseline (`baseline.json`) moves with the tree and is unaffected; the local
  ledger, graph cache and `last-check.json` reset.
- Rewriting `.aidlc/artifacts/` prose.
- Any change to what the harness does. This is a relocation only.
