# Intent: a-baseline-measures-what-ships

- **Date:** 2026-09-09
- **Author:** cwijayasundara
- **Source:** conversation, 2026-09-09 — token and cost-control review against Anthropic's
  Claude Code cost documentation and the "Reducing cost and improving performance with
  Claude Platform" guidance. Captured as the "Context baseline" finding of the cost and context
  control review in `docs/IMPROVEMENT-PLAN.md`, committed at the bound `source_revision`.

## Problem

`.aidlc/lib/baseline.mjs:3` states the harness's own principle: "Keep token usage in check only
means something if a regression fails a build." Neither half of that sentence currently holds.

The metric is wrong. `capture()` at `baseline.mjs:30-35` builds a *synthetic* four-line
session context — project name, check line, budget line, ledger line — and estimates tokens from
that string. What `dispatch.mjs` session-start actually writes to `additionalContext` is that
block plus the map summary, the hubs line, the contract line, `currentLine()`, and one line per
superseded behaviour. Measured on 2026-09-09 at `e5bc7fe`: 2,593 characters, 33 lines,
~649 estimated tokens. `.aidlc/baseline.json` records `session_context_tokens: 52`. The recorded
figure is 8% of the payload, and the gap is not noise — it is a different string.

Twenty-five of the 33 lines are `superseded:` entries, ~76% of the payload. That list is derived
from artifacts on disk and grows with every superseded behaviour; nothing prunes or caps it. The
cost is paid at every SessionStart and re-sent on every turn of that session.

The build never grades it. `baseline` appears in no entry of `[stages]`; `commit` runs `stop`,
`scope-drift`, `budget`, `tamper`, `arch` and `test_quality`. `harness baseline check` exists as a
manual verb that no gate invokes, so a regression in the deterministic token surface fails
nothing. `.aidlc/baseline.json` is dated 2026-08-24 and still carries `wiki_index_tokens: 290`,
a key `capture()` no longer returns — the file predates the current schema and no check noticed.

The `budget` control measures proxies for this surface (`claude_md_lines`, `hooks`, `hook_loc`)
and does fire. It cannot see the payload assembled at runtime, which is the half that grew.

## Proposed outcome

The deterministic token surface the harness controls is measured as the harness actually emits
it, and a regression in it fails a build.

Observable from outside the system:

- `harness baseline capture` records a `session_context_tokens` figure that equals the token
  estimate of the string SessionStart writes to `additionalContext` for this repository, for any
  repository state — not a reconstruction that can drift from it.
- A change that adds a line to the SessionStart payload beyond the recorded tolerance fails a
  gate, naming the metric and the two figures, without anyone choosing to run a verb.
- `.aidlc/baseline.json` contains the metrics the current `capture()` produces and no retired
  keys, and its recorded date is the date those figures were taken.

## Affected users and systems

- `.aidlc/lib/baseline.mjs` — `capture()` and the `RATCHETED` list.
- `.aidlc/hooks/dispatch.mjs` — the `session-start` case, as the single source of the payload.
- `.aidlc/harness.toml` — `[stages]`, if the gate is a stage entry.
- `.aidlc/baseline.json` — recaptured, not hand-edited.
- Every consuming project: the same defect ships in the template, so their baselines understate
  their session cost by whatever their own artifact history adds.
- Agents in every session, who pay the unmeasured payload on every turn.

## Constraints

- Law 11: this is a defect in harness machinery, so it earns a fix, not a new control. The
  measurement already exists and the ratchet already exists; neither is new surface.
- `[limits]` is at 6/7 skills, 4/5 hooks, 4/5 hook bindings, 255/600 hook LOC, 97/120 CLAUDE.md
  lines. No limit is raised to land this.
- Zero dependencies.
- The payload must be measured from the one place that produces it. A second implementation of
  the same string in `baseline.mjs` reproduces the defect being fixed, in a new location.
- `evals/fixtures/` is write-protected. `.aidlc/baseline.json` is regenerated by `capture`, never
  edited to make a check pass.
- The source document is `docs/IMPROVEMENT-PLAN.md`, which is also named in the in-flight
  `graph-first-versus-grep-first` plan's `## Files`. The review section was appended rather than
  edited into that change's rows, so nothing it owns was rewritten; the overlap `harness status`
  reports is real and was accepted by the user on 2026-09-09.
- The recapture will move `session_context_tokens` from 52 to roughly 649. That is a corrected
  measurement, not a regression, and the record should say which it is.

## Open questions

1. Once the payload is visible, does the `superseded:` list stay in it? It is 76% of the cost and
   grows without bound, and `dispatch.mjs` justifies it: a superseded behaviour's spec is never
   edited, so nothing else at session start would ever surface it. Capping it, moving it behind
   `harness status`, or leaving it are different outcomes with different costs, and the choice is
   the human's. This intent measures the payload; it does not decide what the payload contains.

2. Is the gate a `[stages] commit` entry, or does the existing `budget` control absorb it? A
   stage entry keeps the ratchet legible under its own name; folding it into `budget` avoids a
   sixth control at commit. Both fit the limits. This is a design choice the spec should settle
   and the human should see.
