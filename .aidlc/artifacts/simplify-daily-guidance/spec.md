# Spec: simplify-daily-guidance

## Outcome
Concise daily guidance supports sound engineering without invented workflow work.

### B1
Given sufficient requirements and repository evidence, when capturing intent, then ask only
consequential unresolved questions; a coherent outcome may contain multiple related behaviours.
### B2
Given approved behaviour and file ownership, when implementing or refactoring, then make routine
choices autonomously and maintain tests legitimately without weakening required behaviour.
Material design, behaviour or scope changes still require human approval; stale approvals and
unowned paths remain blocked by the existing mechanisms.
### B3
Given unfamiliar code or a defect, when planning or fixing, then inspect system boundaries and
existing patterns, reproduce defects, work in small behavioural slices and verify runtime results.
### B4
Given completed work, when reporting and reviewing, then distinguish defects, evidence and
uncertainty; keep intent, spec/design, plan/proof and review artifacts concise and consistent.

## Design and safeguards
Edit the existing skills, templates and canonical instructions; regenerate the Claude projection.
Keep hooks, roles, limits and approval implementation unchanged. Review guidance may clarify
reporting without granting the evaluator write tools. Compare the same bounded scenarios using
the configured capable generator before and after; report limited sample evidence honestly.

## Out of scope
Full product campaigns and comparative model/graph trials remain items 3 and 4.
